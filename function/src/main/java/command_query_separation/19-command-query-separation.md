# Command Query Separation (CQS)## Bản dịch (VI)Các hàm nên hoặc làm một việc (command), hoặc trả lời một câu hỏi (query), nhưng không nên làm cả hai.- Command: thay đổi trạng thái.- Query: trả về thông tin, không thay đổi trạng thái.Làm cả hai trong cùng một hàm dễ gây nhầm lẫn.Ví dụ trong sách:public boolean set(String attribute, String value);Hàm này vừa:- thay đổi trạng thái (gán attribute)- vừa trả về booleanCall site:if (set("username", "unclebob")) ...Người đọc sẽ bị khựng lại:- Đang hỏi username đã là unclebob chưa?- Hay đang gán rồi kiểm tra thành công?Từ "set" trong ngữ cảnh này có thể hiểu là động từ hoặc tính từ.Đó chính là vấn đề: call site không rõ nghĩa.Giải pháp:Tách command và query.public void setAttribute(String attribute, String value);public boolean attributeExists(String attribute);Hoặc:setAttribute("username", "unclebob");if (attributeExists("username")) { ... }## Nguyên tắc CQS1. Query không được thay đổi trạng thái.2. Command không nên trả về thông tin làm người đọc hiểu nhầm.3. Nếu bạn cần kiểm tra thành công của command → dùng exception thay vì boolean.## Vì sao CQS quan trọng?- Giảm nhầm lẫn ở call site.- Loại bỏ double-take.- Dễ test hơn.- Code dự đoán được.## Bad → Good### Badboolean set(String key, String value);### Goodvoid set(String key, String value);String get(String key);Hoặc nếu cần báo lỗi:void set(String key, String value) throws InvalidKeyException;## Checklist- [ ] Hàm có vừa mutate vừa return dữ liệu không?- [ ] Call site có thể đọc 1 lần là hiểu không?- [ ] Có đang dùng boolean để báo lỗi command không?- [ ] Có thể tách command và query ra không?## Kết luận cần nắm1. Command thay đổi trạng thái.2. Query trả lời câu hỏi.3. Không trộn hai vai trò.4. Nếu command thất bại → dùng exception.
